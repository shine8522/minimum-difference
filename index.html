Minimum Absolute Difference — BST

We want the two closest values in the tree. A BST already keeps left < node < right, so visiting left → root → right (inorder) reads the values out in sorted order. Once values are sorted, the closest pair is always next to each other — so we only ever need to compare previous with current, never the whole list.

void inorder(Node* root, int& prev, bool& hasPrev, int& minDiff) {  if (!root) return;  inorder(root->left, prev, hasPrev, minDiff);  // go left first  if (hasPrev) minDiff = min(minDiff, root->data - prev); // compare  prev = root->data; hasPrev = true;  // current -> previous  inorder(root->right, prev, hasPrev, minDiff); // continue}

Beginner doubts, answered

  • Why inorder? BST order (left < node < right) means left→root→right always reads values ascending.
  • Why only adjacent pairs? In sorted order, any non-adjacent pair has a value sitting between them — that value would give a smaller difference. So the true minimum is always between neighbors.
  • Why no array? After a comparison, the array's older values are never needed again — only the just-visited value matters for the next comparison.
  • Why no abs()? Inorder values only increase, so current − previous is never negative.
  • Why skip the first node's comparison? There's no previous value yet — that's exactly what hasPrev tracks.
  • Is "previous" the parent? No — it's the previous inorder value. For 10, previous is 7 (the last node visited), not 5 (its parent).

Complexity

  • Time — O(n): every node is visited exactly once.
  • Space — O(h): only the recursion stack plus three constants (prev, hasPrev, minDiff) — no array. O(log n) if balanced, O(n) if skewed.
  • A vector-based solution stores all n values first — O(n) extra space. This one never stores more than one value.
BST → inorder → sorted → adjacent → previous + current → difference → minimum → current → previous → repeat
